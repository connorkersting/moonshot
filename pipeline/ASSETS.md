# Assets this repo does not contain

`build.py` reads pre-rendered assets from folders next to it (in the original work folder). They
are binary (PNG sequences, one WAV, one MP4), so they are not committed. What is committed is each
asset's manifest, in `asset_manifests/<folder>/manifest.json`: the recipe, the input hashes, the
renderer version and the sha256 of every frame. `build.py` checks the manifest of a folder before
it opens the files, and refuses to build on a mismatch (`assets_v23.py`, `assets_v25.py`). So a
checkout can tell, exactly, whether what you rendered is what the run used.

Sizes below are from the `v28-final` tag of the pipeline repo, where these were tracked.

## What `fetch_assets.py` covers

It downloads the NASA video, photos and audio, the Commons music and the NASA CGI Moon Kit. It
does not download: the 16 high-resolution Commons scans in `stills_hq` (list and URLs in
CREDITS.md), the Blue Marble clouds texture, the Sonniss bundle, the Blue Marble 21600 px base,
the HDRI or the fonts. The scans (v24 on) and the clouds texture (v25 on) matter only if you rebuild those assets; a checkout that already has the asset folders doesn't need them.

## The Sonniss boundary

The sound-effects bundle is licensed for use in a production but not for redistribution or for AI
training, so it is never in this repo and a full rebuild of the audio needs your own copy.
